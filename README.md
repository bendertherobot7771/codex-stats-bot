# Codex Stats Bot

Codex Stats Bot собирает статистику использования Codex с нескольких Windows-компьютеров и показывает сводку через Telegram-бота, запущенного на Orange Pi или другом Linux-сервере.

Первый рабочий MVP включает Windows-агент, HTTP-сервер, SQLite и Telegram-бота.

Текущая версия: `0.2.0`.

## Цели

- автоматически определять начало и завершение задания Codex;
- считывать недельный процент до и после задания через текущую локальную авторизацию Codex;
- учитывать точные локальные счётчики токенов без передачи содержимого диалогов;
- связывать расход с пользователем и компьютером;
- корректно обрабатывать параллельные задания;
- хранить статистику централизованно и показывать её через Telegram.

## Архитектура

Проект состоит из двух частей:

1. Windows-агент следит за локальными JSONL-журналами Codex, распознаёт события `task_started`, `token_count` и `task_complete`, получает снимки недельного окна и отправляет обезличенную статистику серверу.
2. Сервер на Orange Pi принимает идемпотентные события по HTTP, сохраняет их в SQLite, рассчитывает распределение недельного расхода и отвечает на команды Telegram-бота.

OAuth-токен Codex используется только локальным агентом для запроса текущего лимита и никогда не отправляется на сервер. Тексты запросов, ответы модели и результаты инструментов не собираются.

Агент сначала запрашивает свежий снимок недельного окна через `https://chatgpt.com/backend-api/wham/usage`, используя `~/.codex/auth.json`. Это внутренний, официально не документированный интерфейс Codex, который может измениться. При ошибке агент использует последний снимок из локального журнала с явной отметкой источника.

## Параллельные задания

Сервер группирует пересекающиеся интервалы заданий одного аккаунта и окна сброса. Общий прирост недельного процента учитывается один раз и распределяется между заданиями пропорционально их локальным токенам. Для одиночного задания сохраняется прямой замер; для пересекающихся заданий результат помечается как оценочное распределение.

Такой алгоритм предотвращает двойной учёт, но не может гарантировать абсолютно точное распределение, поскольку формула пересчёта токенов в подписочный недельный лимит OpenAI публично не документирована, а процент может округляться.

## Windows-агент

Агент написан на стандартной библиотеке Python и может запускаться из исходников:

```powershell
py -m agent.codex_stats_agent configure `
  --server-url "http://192.168.32.125:8765" `
  --api-key "ЗАМЕНИТЕ_НА_ОБЩИЙ_СЕКРЕТ" `
  --user-name "Имя пользователя"

py -m agent.codex_stats_agent status
py -m agent.codex_stats_agent watch
```

Команда `status` проверяет локальную авторизацию и показывает текущий недельный процент. `watch` отслеживает только события, появившиеся после первого запуска, и сохраняет позиции файлов, активные задания и очередь недоставленных событий в `%APPDATA%\CodexStatsAgent`.

GitHub Actions проверяет код на Windows и Linux, а затем собирает один `codex-stats-agent.exe`. Для обычного push готовый файл доступен как artifact запуска workflow. Тег вида `v0.1.0` автоматически создаёт GitHub Release, после чего агент можно установить одной командой из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\agent\install.ps1 `
  -ServerUrl "http://192.168.32.125:8765" `
  -ApiKey "ЗАМЕНИТЕ_НА_ОБЩИЙ_СЕКРЕТ" `
  -UserName "Имя пользователя"
```

Установка не требует прав администратора: один `.exe` помещается в `%LOCALAPPDATA%\CodexStatsAgent`, а скрытый запуск при входе создаётся в пользовательской папке автозагрузки. Удаление:

Если репозиторий приватный, установщик автоматически использует сохранённую авторизацию Git Credential Manager. На компьютере без настроенного Git можно временно задать `GITHUB_TOKEN` с правом чтения репозитория либо предварительно скачать exe и выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\agent\install.ps1 `
  -ServerUrl "http://192.168.32.125:8765" `
  -ApiKey "ЗАМЕНИТЕ_НА_ОБЩИЙ_СЕКРЕТ" `
  -UserName "Имя пользователя" `
  -ExecutablePath "C:\Downloads\codex-stats-agent.exe"
```

GitHub-токен используется только во время скачивания и не записывается в конфигурацию агента.

Удаление:

```powershell
powershell -ExecutionPolicy Bypass -File .\agent\uninstall.ps1
```

Локальная конфигурация специально сохраняется при удалении. В ней находится серверный API-ключ, поэтому файл `%APPDATA%\CodexStatsAgent\config.json` нельзя публиковать.

## Состояние установки

- Windows: исходный агент и установочные скрипты готовы; сборка одного `.exe` будет выполняться GitHub Actions.
- Orange Pi: сервер использует только стандартную библиотеку Python 3, SQLite и systemd; `pip`, Docker и отдельная СУБД не нужны.

## Сервер на Orange Pi

Скопируйте или клонируйте репозиторий на Orange Pi и выполните из его корня:

```bash
sudo bash server/install.sh
sudo nano /etc/codex-stats-bot.env
sudo systemctl enable --now codex-stats-bot
systemctl status codex-stats-bot
```

Обязательная настройка:

```dotenv
CODEX_STATS_API_KEY=длинный-случайный-секрет
```

Этот же секрет вводится в установщик каждого Windows-агента. Для создания секрета можно использовать:

```bash
python3 -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Для Telegram создайте бота через `@BotFather` и задайте `TELEGRAM_BOT_TOKEN`. Владелец проекта с Telegram ID `8461749755` задан начальным администратором через `TELEGRAM_ADMIN_CHAT_IDS`. Список доступа хранится в SQLite и сохраняется при обновлениях сервиса. Дополнительные ID из `TELEGRAM_ALLOWED_CHAT_IDS` импортируются как читатели при запуске; дальше ими можно управлять прямо в Telegram.

Администратор добавляет участника командой `/adduser CHAT_ID Имя`. Сам участник может заранее узнать числовой ID через `/whoami`, даже если доступа у него ещё нет. Команда `/users` показывает участников и кнопки удаления. Администратора, заданного в конфигурации, через бот удалить нельзя.

Команды бота:

- `/stats` — сводка текущего недельного окна по именам компьютеров;
- `/weeks` — список всей сохранённой недельной истории с кнопками выбора;
- `/week N` — подробная статистика выбранной недели;
- `/active` — текущие задания;
- `/last` — последние завершённые задания;
- `/whoami` — Telegram chat ID для настройки доступа;
- `/users` — список участников и кнопки удаления, только администратор;
- `/adduser CHAT_ID [имя]` — предоставить доступ, только администратор;
- `/removeuser CHAT_ID` — отозвать доступ, только администратор;
- `/help` — справка.

Все допущенные участники видят общую статистику проекта. Недельной границей считается `reset_at`, полученный из окна квоты Codex, а не календарный понедельник. Завершённые задания хранятся без автоматического удаления, поэтому через `/weeks` и `/week N` доступна вся накопленная история. Внутри недели строки группируются прежде всего по `machine_name`; рядом показывается имя пользователя, заданное при установке агента.

HTTP API:

- `GET /health` — проверка доступности без авторизации;
- `POST /api/v1/events` — события Windows-агентов;
- `GET /api/v1/stats?days=7` — JSON-сводка.

Кроме `/health`, запросы требуют заголовок `Authorization: Bearer <CODEX_STATS_API_KEY>`. Повторная отправка одного `event_id` безопасна и не создаёт дубликат.

По умолчанию сервер слушает все сетевые интерфейсы на порту `8765`. В локальной сети агенты подключаются к `http://192.168.32.125:8765`.

Не пробрасывайте `8765` напрямую в интернет: обычный HTTP раскрывает общий API-ключ при перехвате трафика. Для внешнего доступа направьте TCP `80` и `443` с роутера на Orange Pi и поставьте Caddy перед сервером; backend после этого рекомендуется привязать к `127.0.0.1`. Домен должен указывать на внешний IP. Минимальный Caddyfile:

```caddyfile
stats.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

В Windows-агенте тогда используется только `https://stats.example.com`. До настройки домена и HTTPS доступ оставлен локальным.
- Сборка Windows `.exe`: автоматически через GitHub Actions.

## Ограничения Windows-агента

- Автоматическое распознавание рассчитано на текущий JSONL-формат Codex Desktop/CLI и может потребовать обновления при изменении формата.
- Процент недельного окна обычно округляется, поэтому небольшое задание может дать `0%` при ненулевых токенах.
- Первый запуск не импортирует старые задания, чтобы случайно не отправить исторические данные.
- Для прямого снимка лимита необходима действующая локальная авторизация Codex; OAuth-токен никогда не включается в отправляемые события.

## Проверка

Все тесты используют стандартный `unittest` и не обращаются к реальному аккаунту. В набор входит end-to-end сценарий с двумя условными Windows-агентами, локальным HTTP-сервером и пересекающимися заданиями:

```powershell
py -m unittest discover -s tests -v
```

Ручная проверка текущей авторизации выполняется отдельно командой `status`.

Проверка HTTP-сервера после запуска:

```bash
curl http://127.0.0.1:8765/health
curl -H "Authorization: Bearer $CODEX_STATS_API_KEY" \
  "http://127.0.0.1:8765/api/v1/stats?days=7"
```
